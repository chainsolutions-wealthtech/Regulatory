# CHANGE_MANAGEMENT — Gestion des changements

> **Statut :** `APPLICABLE`

## Processus

1. qualifier la demande et sa source ;
2. identifier documents, données, règles, clauses, preuves et utilisateurs affectés ;
3. rechercher l’existant et les décisions ;
4. définir critères, risques, migration et rollback ;
5. obtenir les validations humaines requises ;
6. exécuter un changement atomique ;
7. vérifier le diff et la non-régression ;
8. mettre à jour état, suivi, TODO, changelog et handoff.

## Changements réglementaires

Ils exigent texte officiel, version, date d’effet, impact sur les packs, exigences, clauses et prospectus existants. Aucun agent ne peut inventer ou activer une règle.

## Exceptions

Toute dérogation est consignée dans `EXCEPTION_REGISTER.md` avec durée, risque, approbation et plan de sortie.

## Checklist

- [ ] demande sourcée ;
- [ ] impact complet ;
- [ ] validation requise ;
- [ ] rollback ;
- [ ] preuves et documentation.
