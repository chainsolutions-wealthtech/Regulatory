# VERSIONING — Politique de versionnement

> **Statut :** `APPLICABLE`

Sont versionnés : sources, exigences, champs, questionnaires, options, règles, clauses, modèles, schémas, documents générés, décisions et manifests.

## Principes

- identifiant stable distinct de la version ;
- date d’effet et période de validité ;
- aucune modification rétroactive d’une version active ;
- compatibilité et migration documentées ;
- historique et `superseded_by` ;
- snapshot reproductible des dépendances ;
- versions de release applicative à définir ultérieurement.

## Clauses réglementaires

Une modification crée une nouvelle version soumise à revue. Les documents historiques continuent de référencer leur version d’origine.

Le schéma précis de versionnement logiciel est `À DÉFINIR — information non fournie ou non vérifiée à ce stade du projet.`
