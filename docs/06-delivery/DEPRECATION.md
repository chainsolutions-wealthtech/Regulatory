# DEPRECATION — Dépréciation

> **Statut :** `À DÉTERMINER`

## Champ futur

APIs, champs, identifiants, questions, clauses, règles, modèles, exports et fonctions.

## Processus

1. identifier consommateurs et versions ;
2. justifier la dépréciation ;
3. annoncer la période de transition ;
4. fournir remplacement et migration ;
5. maintenir compatibilité ;
6. mesurer l’usage ;
7. retirer seulement après critères et approbation ;
8. conserver historique et redirections documentaires.

## Règles

Les identifiants réglementaires existants ne peuvent pas être supprimés ou renommés sans migration formelle. Une version active n’est jamais modifiée rétroactivement. Les délais et responsables sont `À DÉFINIR — information non fournie ou non vérifiée à ce stade du projet.`
