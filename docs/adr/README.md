# ADR — Mode d’emploi

> **Statut :** `APPLICABLE`  
> **Autorité :** `docs/DECISIONS.md` conserve le registre historique; ce dossier détaille les décisions structurantes futures.

## Quand créer une ADR

Créer une ADR pour une décision durable affectant architecture, source de vérité, gouvernance, données canoniques, réglementation, sécurité, delivery ou migration documentaire. Ne pas créer d’ADR pour une action courante ou une simple correction.

## Contenu obligatoire

Identifiant, titre, date réelle, statut, tâche, décisions historiques liées, contexte, options, décision, conséquences, risques, migration, rollback et preuves.

## Cycle de vie

`PROPOSED → ACCEPTED → SUPERSEDED` ou `REJECTED`. Une ADR n’est jamais supprimée. Une nouvelle ADR remplace explicitement l’ancienne.

## Règles IA

L’IA peut préparer une ADR mais ne peut pas inventer une décision, une source ou une approbation. Le statut `ACCEPTED` doit correspondre à une décision réelle autorisée.

## Checklist

- [ ] décision historique recherchée ;
- [ ] source et tâche liées ;
- [ ] conséquences et rollback décrits ;
- [ ] validation réelle enregistrée.
